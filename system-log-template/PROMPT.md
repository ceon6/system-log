# SYSTEM LOG 작성 지침 (AI용)

이 저장소의 `TEMPLATE.md` 형식으로 프로그램의 시스템 로그(구축 및 버전 명세서)를 작성·갱신한다.
요청자는 이 저장소 링크와 함께 대상 프로그램 자료(코드 repo, 작업 대화, 기존 노션 페이지 등)를 준다.

---

## 0. 작성 전 확인

다음 중 하나라도 불분명하면 작성하지 말고 먼저 질문한다.

- 신규 작성인지, 기존 로그에 새 버전을 추가하는 것인지
- 이번 변경이 몇 번 버전에 해당하는지 (아래 2. 버전 규칙으로 판단이 갈리는 경우)
- 출력 위치: 노션 페이지 / repo 안 `SYSTEM_LOG.md`

## 1. 근거 자료 읽기

- 코드·커밋·실행 로그·대화 기록에서 **실제로 확인된 사실만** 쓴다.
- 확인 수준을 구분해 적는다.
  - 실행·대조로 확인한 것 → "확인", "일치 확인", "N건 정상 처리 로그 확인"
  - 코드만 반영하고 실사용 미확인 → "반영(실사용 미확인)"
  - 확인 못 한 것 → "미확인:" 항목으로 별도 기재
- "반영 확인"과 "재계산", "테스트"와 "실사용"을 섞지 않는다.

## 2. 버전 규칙

| 버전 | 의미 | 표기 |
|---|---|---|
| `v1.0.0` | 설계 ~ 테스트 종료까지 상용화 이전 전 과정을 하나로 묶음 | 🔴(PoC) 또는 🟡(운영 준비), 일반 목록 |
| `v2.0.0` | 실무 환경에서 정식 사용 시작 | 🟢, 일반 목록 |
| `v2.Y.0` | 기능 추가, 처리 규칙·보안·구조 변경 | 토글 |
| `v2.y.Z` | 동작 규칙 변화 없는 버그 수정 | 토글 |
| `v3.0.0` | 실행 환경·아키텍처 전면 교체 (예: 로컬 → 서버리스) | 새 섹션 |

- 가장 최근 버전 제목 끝에만 `(Latest)`를 붙이고, 이전 버전에서는 뗀다.
- 운영 전 단계면 v2.0.0 섹션은 만들지 않는다.

## 3. 섹션별 작성 기준

**머리 인용**
- 문서 상태: 🔴 PoC / 🟡 운영 준비 / 🟢 Production Ready 중 하나 + 현재 버전 + 한 줄 설명
- 최종 수정일: 이번 작성일로 갱신
- 대상 범위: 입력 → 출력, 사용 채널, 사용자 범위, 처리 규모(거래처 수·인원 등)

**1. 개요**
- 핵심 기능은 3~4개. 각 항목에 사람이 하는 일과 자동으로 되는 일을 구분해 쓴다.
- 데이터 흐름은 `[1. ...] ➔ [2. ...]` 한 줄.
- 구성 요소 표에는 파일명을 `코드체`로, 실행 환경·리전·배포 주소를 적는다.

**2. 비즈니스 로직 표**
- 세무 산식·절사·기한 등 법적 근거가 있으면 조문까지 적는다 (예: 국고금 관리법 §47①).
- 비고 열에는 "코드에서 어떻게 처리하는지"를 쓴다. 규칙 설명을 반복하지 않는다.
- 보안·로그, 예외 처리 행은 항상 둔다.

**3. 버전 이력**
- 각 줄은 `[태그]`로 시작한다. 주로 쓰는 태그:
  `[설계]` `[핵심 구현]` `[구조 개정]` `[검증]` `[테스트]` `[화면 구현]` `[규정 수립]`
  `[운영 기준]` `[운영 준비]` `[운영 안착]` `[실무 실행]` `[연동 정비]` `[데이터 정합성]` `[보안]`
- 토글 안은 `변경 요약`(1~2문장) + `세부 내역`(목록) 구조. 세부 내역 마지막에 검증 방법과 미확인 사항을 둔다.
- 날짜는 `YYYY-MM-DD`, 기간은 `MM-DD ~ MM-DD`.
- 필요하면 마지막에 "작성 시점 운영 상태" 토글을 둔다(건수·대기열·확인 못 한 배포 상태 등).

## 4. 기존 로그 갱신 시

- 기존 버전 항목은 수정하지 않는다. 사실 오류가 있으면 요청자에게 먼저 알린다.
- 새 버전 토글을 맨 아래(최신)에 추가하고 `(Latest)` 위치, 문서 상태, 최종 수정일만 바꾼다.
- 개요·비즈니스 로직 표는 이번 변경으로 내용이 달라진 행만 고친다.

## 5. 문체

- 개조식, 명사형·"~함/~됨" 종결. 과장 표현·상투어 금지.
- 고객·직원이 보는 용어 위주로 쉽게 쓰되, 파일명·함수·설정값은 `코드체`.
- 이모지는 양식에 있는 것(⚙️📌🎯🔄🏛️🔴🟡🟢)만 쓴다.

## 6. 보안 (반드시 지킴)

로그에 아래를 넣지 않는다. 근거 자료에 있으면 빼고, 빠졌다는 사실만 요청자에게 알린다.

- API 키, 토큰, 비밀번호, Signing Secret, 서비스계정 정보
- 고객 실명, 주민등록번호, 사업자번호 전체(필요 시 끝 5자리), 세액·급여 등 금액
- 직원 개인 연락처, 개인 계정 이메일

## 7. 출력 형식

| 출력 위치 | 토글 | 표 |
|---|---|---|
| repo `SYSTEM_LOG.md` | `<details><summary>` | 마크다운 표 |
| 노션 페이지 | 노션 토글 블록 | 노션 표(머리글 행 켬) |

작성 후 요청자에게는 "무엇을 근거로 썼는지 / 미확인으로 남긴 항목 / 보안상 뺀 항목"만 짧게 보고한다.
